MINIRETO 1 - RUEDA LIBRE
========================

1. Solicitud de la pagina de inicio
-----------------------------------
URL del documento: http://127.0.0.1:5500/index.html
Protocolo: HTTP
Host: 127.0.0.1 (direccion local / loopback)
Puerto: 5500
Ruta: /index.html
Metodo: GET
Codigo de estado observado: 200 OK (GET /index.html en Live Server)

URL completa: http://127.0.0.1:5500/index.html
Live Server registra el metodo GET y responde 200 OK para el documento.
En DevTools > Network, seleccionar la solicitud de tipo document para revisar
metodo y estado; en Elements se puede inspeccionar la estructura HTML recibida.

2. Solicitud de una ruta inexistente
------------------------------------
URL: http://127.0.0.1:5500/promociones.html
Protocolo: HTTP
Host: 127.0.0.1
Puerto: 5500
Ruta: /promociones.html
Metodo: GET
Codigo registrado: 404 Not Found
Significado: el servidor fue encontrado, pero no existe un recurso para esa
ruta. En Live Server puede mostrarse el mensaje "Cannot GET /promociones.html".

3. Rol de las tecnologias
-------------------------
HTML define la estructura y el contenido, por ejemplo el titulo, la navegacion
y las secciones de alquiler de bicicletas.
CSS controla la presentacion visual, por ejemplo los colores, el espaciado y
la adaptacion del menu a pantallas pequeñas.
JavaScript agrega comportamiento, por ejemplo validar los datos de un
formulario de reserva antes de enviarlo.

4. Rutas relativas del sitio
----------------------------
La navegacion compartida usa enlaces relativos. Desde index.html se antepone
paginas/ para abrir las paginas internas; desde paginas/ se usa ../ para subir
a la portada y el nombre del archivo para navegar entre paginas de esa carpeta.

Origen                  | Destino                 | Ruta escrita
------------------------|-------------------------|------------------------
index.html              | index.html              | index.html
index.html              | paginas/tarifas.html    | paginas/tarifas.html
index.html              | paginas/reservas.html   | paginas/reservas.html
paginas/tarifas.html    | index.html              | ../index.html
paginas/tarifas.html    | paginas/tarifas.html    | tarifas.html
paginas/tarifas.html    | paginas/reservas.html   | reservas.html
paginas/reservas.html   | index.html              | ../index.html
paginas/reservas.html   | paginas/tarifas.html    | tarifas.html
paginas/reservas.html   | paginas/reservas.html   | reservas.html

Día 2: Esquemas de regiones de cada página.

MINIRETO 5 - ESQUEMAS SEMANTICOS
================================

Inicio (index.html)
body
|- header
|  |- logo y nombre del negocio
|  `- nav principal
|- main
|  |- h1 y presentacion
|  |- section: ¿Quienes somos? (beneficios en lista)
|  |- section: Nuestros servicios
|  |  |- article: Alquiler de bicicletas
|  |  |- article: Recorridos guiados
|  |  `- article: Taller basico y mantenimiento
|  |- section: ¿Como alquilar? (pasos en lista)
|  `- section: Encuentranos (mapa y correo)
`- footer: nombre, correo y año

Tarifas y recorridos (paginas/tarifas.html)
body
|- header
|  |- logo y nombre del negocio
|  `- nav principal
|- main
|  |- h1
|  |- section: Tarifas de alquiler (tabla)
|  |- section: Recorridos guiados (tabla)
|  `- section: Informacion importante
|     `- aside: nota, horarios y lista de que llevar
`- footer: nombre, correo y año

Reservas (paginas/reservas.html)
body
|- header
|  |- logo y nombre del negocio
|  `- nav principal
|- main
|  |- h1
|  |- section: Contacto (correo)
|  `- section: Horario de atencion
|     `- aside: dias y horarios en lista de definiciones
`- footer: nombre, correo y año

No se requieren div ni span: header, nav, main, section, article, aside y
footer expresan las regiones y relaciones necesarias en estas tres paginas.

MINIRETO 6 - DECISIONES DE CONTROLES DEL FORMULARIO
===================================================
1. El numero de documento usa input type="text" para conservar posibles ceros
	iniciales y formatos que no son cantidades para calcular.
2. El tipo de bicicleta usa botones radio con un mismo name porque se debe
	seleccionar una sola opcion de un grupo excluyente.
3. El plan y el recorrido usan select porque cada campo ofrece un conjunto
	cerrado de opciones y solo se elige una.
