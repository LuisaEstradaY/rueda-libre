3. Rol de las tecnologias
-------------------------
HTML define la estructura y el contenido, por ejemplo el titulo, la navegacion
y las secciones de alquiler de bicicletas.
CSS controla la presentacion visual, por ejemplo los colores, el espaciado y
la adaptacion del menu a pantallas pequeñas.
JavaScript agrega comportamiento, por ejemplo validar los datos de un
formulario de reserva antes de enviarlo.

4. Rutas relativas del sitio
----------------------------
La navegacion compartida usa enlaces relativos. Desde index.html se antepone
paginas/ para abrir las paginas internas; desde paginas/ se usa ../ para subir
a la portada y el nombre del archivo para navegar entre paginas de esa carpeta.

MINIRETO 6 - DECISIONES DE CONTROLES DEL FORMULARIO
===================================================
1. El numero de documento usa input type="text" para conservar posibles ceros
	iniciales y formatos que no son cantidades para calcular.

	cerrado de opciones y solo se elige una.

MINIRETO 10 - CASCADA, ESTADOS Y ESPECIFICIDAD
=============================================
El menu usa id="menu" en la lista; cada enlace actual lleva class="activo" y
aria-current="page". La regla del compañero #menu a tiene especificidad
(1,0,1), mientras .activo tiene (0,1,0). Aunque .activo aparezca despues,
#menu a gana por el ID, y su color queda como declaracion aplicada en Styles;
el color de .activo aparece tachado. La correccion #menu a.activo tiene
(1,1,1), supera ambas reglas y muestra Verde Ruta sin usar !important.

Los enlaces del menu usan el selector descendiente #menu a. Hover emplea
Azul Noche sobre Naranja Pedal (7.20:1); foco del menu usa texto blanco sobre
Verde Ruta (5.31:1) con contorno Azul Noche. Los enlaces normales usan Verde
Ruta sobre Crema (4.93:1) y subrayado al pasar el cursor. Los botones base usan
blanco sobre Verde Ruta (5.31:1); hover y foco usan Azul Noche sobre Naranja
(7.20:1). Campos y boton de envio tienen contorno de foco visible Azul Noche.

En Styles se observa #menu a (1,0,1) por encima de .activo (0,1,0): el color
gris prevalece y la declaracion verde de la clase aparece tachada. #menu a.activo
(1,1,1) resuelve el conflicto sin !important. En DevTools :hov, el hover del
menu/boton presenta fondo naranja y texto azul; el foco muestra contorno azul.
El foco de teclado en Nombre completo muestra contorno solido azul de 3 px.
La hoja compartida esta en css/styles.css; inicio la carga con css/styles.css
y las paginas internas con ../css/styles.css.

MINIRETO 13 - LAYOUT CON GRID Y FLEXBOX
======================================
Decisiones de layout
--------------------
Caso             | Tecnica  | Motivo segun dimensiones
-----------------|----------|------------------------------------------------
Portada          | Grid     | Dos columnas (texto e imagen) requieren dos
                 |          | regiones; las columnas usan fr y el texto se
                 |          | centra verticalmente con align-items.
Galeria de rutas | Grid     | Tres tarjetas ocupan columnas simultaneas en
                 |          | una fila; repeat() y fr reparten el espacio.
Reservas         | Grid     | Formulario e informacion son dos columnas con
                 |          | proporcion 2:1, definida con 2fr y 1fr.
Fila del         | Grid     | Documento y celular comparten una fila de dos
formulario       |          | columnas; en pantallas estrechas pasan a una.
Encabezado       | Flexbox  | Logo y navegacion se distribuyen en un eje;
                 |          | align-items y justify-content los alinean.
Pie              | Flexbox  | El contenido fluye y se reparte en un eje;
                 |          | gap y flex-wrap permiten que se adapte.

Grid se eligio para las areas con filas/columnas y relaciones en dos
dimensiones. Flexbox se reservo para alinear elementos en un solo eje. Las
rejillas de portada, galeria, reservas y formulario usan fr; en movil se
apilan para mantener la lectura y evitar desbordamientos. La navegacion, la
flota y la validacion nativa del formulario permanecen sin cambios funcionales.

MINIRETO 14 - RESPONSIVE MOBILE-FIRST (v1.5)
============================================
Comportamiento por ancho
------------------------
Viewport | Encabezado y pie                         | Portada / rutas / flota
---------|------------------------------------------|-------------------------
360 px   | Marca arriba, menu centrado debajo;      | 1 columna en cada rejilla.
         | pie centrado y con ajuste de linea.      |
768 px   | Marca y menu en una fila; pie Flexbox    | Portada 2; rutas 2; flota
         | en fila con wrap si hace falta.          | 2 columnas.
1280 px  | Marca y menu alineados a lados opuestos; | Portada 2; rutas 3; flota
         | pie Flexbox distribuido.                 | 3 columnas.

Reservas se apila en una columna a 360 px y usa Grid 2fr/1fr desde 768 px.
Los campos de documento y celular tambien se apilan en movil y comparten dos
columnas desde tablet. Grid resuelve filas y columnas (dos dimensiones) en
portada, rutas, flota y reservas; Flexbox alinea el encabezado y el pie sobre
un eje. Las imagenes usan max-width: 100% y height: auto.

Problemas responsive encontrados y solucionados
------------------------------------------------
1. Las tablas de tarifas no cabian en el ancho movil; la de cinco columnas
   necesitaba desplazamiento lateral. Se quitaron overflow/display de scroll,
   se aplico table-layout fixed, tipografia de 12 px, menos relleno y quiebres
   de texto. En 360 px ambas tablas miden 328 px y sus celdas no desbordan.
2. Portada, rutas y reservas empezaban con columnas de escritorio, demasiado
   estrechas en celular. Se dejaron en una columna como base y se restauraron
   las columnas de Grid a partir de 768 px.
3. En celular, la marca y la navegacion no quedaban centradas como una columna.
   El encabezado ahora apila y centra ambos elementos en el estilo base; desde
   768 px vuelve a una fila con espacio entre marca y menu.
4. Las imagenes dependian de reglas separadas por seccion. Se agrego una regla
   global fluida (max-width: 100%, height: auto) para que respeten siempre el
   ancho de su contenedor.

Tres conflictos de cascada observados en DevTools y sus soluciones
-----------------------------------------------------------------
1. Bootstrap aplica una tipografia de sistema al body. La regla body de
   styles.css, cargada despues, restablece Times New Roman y los colores de
   marca sin !important.
2. Los enlaces .nav-link reciben el azul predeterminado de Bootstrap. El
   selector #menu a de styles.css tiene mayor especificidad y aplica el gris
   de marca; el estado activo usa verde.
3. Las variables de tabla de Bootstrap interferian con el fondo y el texto
   propios de los encabezados. Se fijaron --bs-table-bg, --bs-table-color y
   sus variables de estado en los encabezados de tabla y fila. Los botones
   .btn-success conservan el verde/naranja de marca con variables --bs-btn-*.

Comparativa final de CSS y tiempo
---------------------------------
En el commit v1.5 e286be9, css/styles.css tenia 493 lineas. La version migrada
tiene 197 lineas: 296 menos, una reduccion del 60.0%. Se verifico el historial
local con git show e286be9:css/styles.css y se conto el archivo actual.

El tiempo de construccion v1.5 con CSS propio no se registro en su momento. En
esta migracion tampoco se inicio un cronometro antes de trabajar, asi que no se
inventa una duracion retrospectiva para v2.0-beta. Como referencia separada y
medida, la prueba de grilla Bootstrap del MiniReto 5 tomo 1 minuto y 47 segundos
para una flota de siete tarjetas, no para migrar el sitio completo. No hay datos
de tiempo comparables para las dos versiones; en una siguiente iteracion se
debe iniciar el cronometro al comenzar cada version.

Bootstrap aporto grilla responsiva, gutters y utilidades listas para usar y
redujo el CSS propio en un 60.0%. A cambio, el HTML requiere mas clases de
utilidad y el sitio depende del CDN. Se conservaron estilos propios donde se
necesitaba identidad de marca y control de tablas y formularios. Conclusion:
Bootstrap reduce el CSS de distribucion y acelera los layouts repetibles, pero
no elimina la necesidad de CSS propio para la identidad ni de validar la
cascada y los breakpoints.
